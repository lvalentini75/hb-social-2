# HB Social 2.0 — Agent rules

You are building HB Social, a premium international social network for hunters.
Launch market Italy; designed for France, Spain, Germany/Austria, UK from day one.
Flutter (web + iOS + Android, one codebase), Supabase backend, Riverpod, go_router.
UI copy is Italian (plus EN/FR/ES/DE translation files). Code, identifiers and comments are English.

## Start of EVERY task — single development track
1. Read `docs/STATUS.md` first. It names the CURRENT prompt (Pxx). Work only on that prompt.
2. Read the matching row of `docs/ROADMAP.md` (scope, backend, acceptance). Nothing outside that row.
3. If scope, data, behavior or navigation is ambiguous, ask questions and STOP until answered.
4. At the end of the task: update `docs/STATUS.md` (mark the prompt done, list files touched, open issues) and, if a decision was made, append one line to `docs/DECISIONS.md`.
5. Never refactor, rename or "improve" code outside the current prompt. Never reintroduce something that STATUS marks as removed.

## Non-negotiable rules
1. No fake data, ever. Never use mock, fake, in-memory, hardcoded or "sample" data in app code; lists without data show a designed empty state. P01 and P02 (visual foundation) build shells, HB* widgets and screens against the domain model in `ARCHITECTURE.md` with empty states only. From P03 on, backend first: never build or wire a screen before its tables exist in `lib/supabase/*.sql`, and every screen reads real tables.
2. One implementation per feature. Never leave a V1 and a V2 side by side.
3. Every table with membership (groups, forums, pages, conversations, ad accounts, events) gets SECURITY DEFINER helper functions (`is_<x>_member`, `is_<x>_manager`) BEFORE any RLS policy. A policy must never query its own table.
4. Every new table: `enable row level security`, indexes on filter columns, `if not exists` everywhere, counters updated by triggers, `created_at timestamptz not null default now()`, `country_code text` on every hunting-domain and content table.
5. Write schema changes ONLY into `lib/supabase/pending_migrations.sql`, idempotent. Never deploy them: the developer reviews and deploys from the Schema Deployment panel.
6. Pages inside the shell never return a Scaffold. The shell is the only Scaffold. Never `SingleChildScrollView` as a page root: `CustomScrollView` + slivers, or `Column` + `Expanded`.
7. Never show technical errors to users. Map Supabase/Postgrest errors to short Italian messages via `AppException`.
8. Only URL and anon key in the client (`lib/supabase/supabase_config.dart`). Never a service_role key, never secrets.
9. No code-generation tools (no freezed, json_serializable, build_runner, gen-l10n). Write `fromJson`/`toJson` by hand. i18n via `easy_localization` with JSON assets.
10. Every user-visible string goes through a translation key (`'feed.empty_title'.tr()`), added to ALL five files in `assets/translations/` (it, en, fr, es, de). No hardcoded UI text, ever.
11. Money: integers in minor units + `currency_code`; never doubles. Display with the user's currency through `MoneyFormatter`.
12. Dates: `timestamptz` in DB, UTC in transit, local in UI; relative dates with `timeago` in the user's locale.

## Project structure (see ARCHITECTURE.md)
lib/core/{config,router,theme,widgets,services,l10n,i18n}
lib/features/<feature>/{data,domain,presentation,providers}

assets/translations/{it,en,fr,es,de}.json
docs/{ROADMAP.md, STATUS.md, DECISIONS.md, DESIGN_SYSTEM.md}

## Design system (full spec in docs/DESIGN_SYSTEM.md — tokens live in lib/core/theme/)
Colors: page #F6F7F8, surface #FFFFFF, soft #F2F4F5, hover #EEF2EF, divider #E7EBE8, border #E3E7E4; text #111715, textSecondary #66706B, textTertiary #8A948F; primary #2E7D45, primaryDeep #225E34, primarySoft #EAF5EE, primaryOutline #A7CCB4; success #22A06B, warning #C98912, error #D14343, info #2E6BDE.
Font Inter. Radius 10/14/18/22/28/999. Shadows level1–3 (never borders on cards). White first; green only for the single primary CTA per screen and active states; no gradients; media edge-to-edge; every list has empty/loading/error states.
Shared widgets in `lib/core/widgets/`: HBCard, HBButton (primary/secondary/soft/ghost/icon), HBInput, HBChip, HBSegmentedTabs, HBEmptyState, HBBadge, HBAvatar, HBStatusChip. Build screens from these; never raw Material widgets for these roles.
Admin console is the one place with a dark sidebar (#151C18); everything else is white-first.

## Conventions
- Repositories return models or throw `AppException(messageKey)`. Providers are Riverpod `AsyncNotifier`/`FutureProvider`.
- Pagination cursor-based on `(created_at, id)`, page size 20.
- Storage paths `<bucket>/<user_id>/<uuid>.<ext>`; public buckets for media, private for documents.
- Every task response ends with a "How to verify" list (3–6 steps a human can follow in the preview).
