# HB Social 2.0 — Decisions log

| Date | Decision | Why |
|---|---|---|
| 2026-10-02 | Rebuild from zero on Dreamflow; old codebase kept only as reference | Two parallel codebases, seven models, database lost |
| 2026-10-02 | Backend first with real sample data in Supabase; no mock in app code | The 2025 Dreamflow build was 85% UI / 0% backend |
| 2026-10-02 | Schema changes only via `pending_migrations.sql` reviewed by a human before deploy | Manual SQL in dashboard caused untracked, half-applied migrations |
| 2026-10-02 | SECURITY DEFINER helpers before any RLS policy on membership tables | RLS infinite recursion (42P17) hit twice in the old project |
| 2026-10-02 | Multi-country, multi-language, multi-currency from the first schema | Target markets IT, FR, ES, DE/AT, UK; refitting later costs a rewrite |
| 2026-10-02 | easy_localization (JSON) instead of gen-l10n | Dreamflow cannot run code generation |
| 2026-10-02 | Edge Functions deployed outside Dreamflow with Supabase CLI | Dreamflow does not support Edge Functions |
| 2026-10-02 | Firearms/ammo in marketplace only as mediated showcase (no in-app payment) | Italian law + App Store / Play policies |
| 2026-10-02 | Phase 0 order: graphics first (P01 app, P02 admin) with empty states and zero fake data, then Supabase schema + sample data (P03), then screens wired to real tables (P04, P05) | Owner wants to see the product before the backend; screens are built against the domain model in ARCHITECTURE.md so wiring in P04 does not restructure them |
| 2026-10-02 | Prompt numbering P00–P49 is fixed; the doc "Roadmap Rebuild da Zero", `docs/ROADMAP.md` and `docs/STATUS.md` always use the same numbers | One development track: a prompt name must mean the same thing everywhere |
| 2026-10-04 | No authentication during the visual phase: every fake login, demo user and session simulation removed (`user_providers.dart`, `app_user.dart` and their call sites). Until P03 there is NO auth redirect: `initialLocation` stays `/welcome` but `/` and every shell route is reachable directly. `authStateProvider` reads the abstract `AuthRepository`, whose only implementation is `UnauthenticatedAuthRepository`. The signed-out state is visible as a guest `HBAvatar` in the shell and a "Accedi per vedere il tuo profilo" empty state on Profile. Welcome shows an "Esplora l'app" ghost link in `kDebugMode` only; Login/Signup forms only reveal the translated notice "Il login si attiva con il collegamento a Supabase (P03)" | A simulated session is fake data by another name (AGENTS rule 1) and would have had to be ripped out in P03; a visual phase needs every screen reachable without an account |
| 2026-10-04 | Single button/input family: deleted `AppPrimaryButton`/`AppSecondaryButton`/`AppTextLink`, `AppTextField`, `SocialAuthButtons` and `showComingSoon` in favour of `HBButton`, `HBInput`, `HBChip` and routed "In arrivo" pages | AGENTS rule 2 (one implementation per feature); social sign-in buttons promised a capability that does not exist |
| 2026-10-04 | Shell navigation moved to `StatefulShellRoute.indexedStack` with 11 branches, split into `web_shell.dart` / `mobile_shell.dart` per ARCHITECTURE.md; `/` is the home route (was `/home`) | Per-destination navigation state and the 9-item sidebar required real routes instead of snackbars |
| 2026-10-03 | P01 part a: renamed shared widgets in place (`EmptyState`→`HBEmptyState`, `UserAvatar`→`HBAvatar`) instead of adding new HB* versions alongside them; kept `app_theme.dart` as the single token file rather than splitting into the per-token files named in `ARCHITECTURE.md` | AGENTS rule "one implementation per feature, never V1/V2 side by side"; splitting tokens now was not requested and added restructuring risk with no behavior change |
| 2026-10-04 | P01 part b: no per-item row widgets built for Groups/Forum/Pages/Messages/Notifications/Search (only loading/error/empty states); every "not implemented" action (create group, new thread, new page, new message, mark all read) reuses `common.coming_soon_title`/`common.coming_soon_message` instead of per-feature copy; domain models named `CommunityPage` and `AppNotification` to avoid shadowing Flutter's `Page`/`Notification` | With zero sample data allowed, a list item can never actually render, so a row widget would be dead code until P03/P04; reusing 2 i18n keys across 6 features avoids ~10 near-duplicate key pairs × 5 languages; avoiding SDK class name collisions keeps imports unambiguous |
| 2026-10-04 | Public profile (`/u/:username`) added as a top-level `GoRoute` outside the shell with its own `Scaffold`/`AppBar`, separate from the existing authenticated `/profile` shell page | Shared-link profiles must be reachable without the bottom nav / sidebar chrome, same precedent as Welcome/Login/Signup |
| 2026-10-04 | P01b rework: the shell-level `RightRail` was removed; Home keeps it through `PageColumns`, each other screen owns its optional 340px rail, and `/u/:username` moved into the Profile shell branch without its own `Scaffold` | The approved desktop pattern requires page-specific supporting content while preserving consistent responsive columns and shell navigation |
| 2026-10-03 | Modello UI primario in Dreamflow: GPT 5.6 Sol; Sonnet 5 riserva; Opus 5 per schema e RLS | Sonnet 5 si interrompe spesso con errori interni |
| 2026-10-03 | Preview features (Welcome "Esplora l'app", admin "Anteprima console", /dev/design-system) legate a Env.previewEnabled (flavor dev) e mai a kDebugMode | La build publicata su share.dreamflow.app è release mode, quindi kDebugMode=false; le preview scomparivano in preview pur essendo dev |
